# Generating input data (Synthea)

All input to this pipeline is **100% synthetic**, generated by
[Synthea](https://github.com/synthetichealth/synthea). No real PHI, ever.

> On Windows, use the PowerShell commands in [`setup_windows.md`](setup_windows.md) instead of the bash snippets below.

## Primary path — Synthea (run locally)

Requires Java 11+.

```bash
# 1. Get the release jar (once)
curl -L -o synthea-with-dependencies.jar \
  https://github.com/synthetichealth/synthea/releases/download/master-branch-latest/synthea-with-dependencies.jar

# 2. Generate ~50 patients, FHIR R4, into data/fhir/
java -jar synthea-with-dependencies.jar \
  -p 50 \
  --exporter.fhir.export true \
  --exporter.fhir.use_us_core_ig false \
  --exporter.baseDirectory ./data \
  Massachusetts
```

Output lands in `./data/fhir/*.json`. Each file is a FHIR `Bundle`
(`resourceType: "Bundle"`) with an `entry[]` array; every entry wraps a
`resource` identified by its `resourceType` (`Patient`, `Encounter`,
`Condition`, `Observation`, `Procedure`, `MedicationRequest`, ...).

Notes:
- `-p 50` = living-patient count. Bump to 1000 later for a scale story.
- Swap `Massachusetts` for any US state (affects addresses/demographics).
- Synthea also emits `hospitalInformation*.json` and `practitionerInformation*.json`
  bundles — the parser dispatches on `resourceType`, so these pass through harmlessly.

## Fallback path — offline fixtures

When Synthea can't run (no network / no Java), generate Synthea-shaped R4
bundles for parser development:

```bash
python scripts/generate_sample_bundles.py --patients 10 --out data/fhir
```

These mirror Synthea's structure (bundle → entry → resource, `urn:uuid`
references, US Core race/ethnicity extensions, `value[x]` polymorphism on
Observations) so the parser is exercised against the same shapes. They are
**dev fixtures, not a substitute for Synthea** — the real portfolio run
uses the Synthea command above.
